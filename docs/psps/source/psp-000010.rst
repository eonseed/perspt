========
Abstract
========

Perspt's control plane accepts only verified completions: every accepted state
passes the Lyapunov gate on the realized candidate, every effect is mediated by
the admissibility kernel, and every claim is conditional on ledgered evidence.
:psp:`000009` made that discipline live. What it did not give the platform is a
way to *look for* an acceptable candidate beyond correcting one proposal on one
route, or a way to *speak to* each model in the form that model actually
follows. In practice both gaps show up as the same failure: the agent burns its
rejection budget re-correcting a candidate that a different strategy, a
different route, or a differently phrased brief would have carried to descent.

This PSP adds two control-plane layers and changes no acceptance rule:

* A **bounded search forest** :math:`\mathcal{E}_k` of speculative branches.
  Every branch begins at the accepted state :math:`x_k`, may move uphill
  internally, and may fail completely. Only a measured branch candidate,
  submitted through the ordinary gate, can become :math:`x_{k+1}`. Each
  submission consumes exactly one gate decision, so Paper II Lemma 1's finite
  bound survives search unchanged. Rejected and abandoned branches leave the
  accepted workspace and the accepted ledger projection unchanged, and leave
  behind only deterministically supported no-good constraints and a bounded
  evidence digest.

* **Provider-conditioned prompt programs** :math:`\pi_{p,m,s}`.
  ``perspt-sdk`` gains restricted template primitives; the platform envelope
  templates live in ``perspt-agent`` (the composition root that owns every
  actor call site); each domain package owns complete provider-specific
  templates for its stages. A compiled program carries template ids, versions,
  and content hashes into the ledger and the ``ControlFrame``, so replay and
  resume reconstruct the exact bytes every model saw. Prompt selection is
  keyed by transport adapter and model family — never by the configured
  provider id — with exact-model overrides. Templates present typed state;
  they cannot mint or widen authority.

The architecture separates three objects — the accepted task trajectory
:math:`\mathcal{A}`, the speculative search forest :math:`\mathcal{E}_k`, and
the provider-conditioned controller :math:`\pi_{p,m,s}` — and proves the
separation rather than asserting it: gate-decision conservation, accepted-fold
invariance under discarded search events, bounded search termination, and
replay determinism over compiled programs are stated and proved in the Formal
Model section, each reduced to a result of Papers I–III.

The PSP also pays four enforcement debts that these layers depend on and that
:psp:`000009` specified but left unwired: the finite-decision bound becomes an
enforced predicate rather than a documented intention; ``HardGatePolicy``
becomes the authoritative source of required verifier stages; the architect's
graph update passes through the ``UpdateGraph`` capability and the full
admissibility kernel instead of bypassing both; and the accepted-projection
fold is re-keyed by candidate identity so that multiple candidates at one node
generation no longer overwrite one another in replay.

Structured verifier adapters (rustc/cargo JSON, pyright JSON and pytest
reports, tsc machine output) replace text-line scraping, and a typed
``CorrectionPacket`` replaces the single correction string, so search branches
receive directions worth branching on. All stochastic actors — worker,
explorer, architect, adjudicator, summarizer — run through one
``ActorTurnRunner`` with raw-observation-before-parse recording. Node winners
accumulate in a graph staging root and promote atomically only after a global
integration gate, closing the composition hole where two independently
verified nodes fail together.

The existing ensemble and exploration APIs (``EnsemblePolicy``,
``EnsembleConfig``, ``[ensemble]``, ``ExplorationBudget``,
``ExplorationReport``) are removed without compatibility aliases and replaced
by the search plane and an ``[exploration]`` configuration. ``simple-chat``
remains untouched and loads none of this.

==========
Motivation
==========

Verified Completion Without Search
==================================

The gate is a filter, not a generator. :psp:`000009` system 6 gives the loop
one candidate workspace per attempt and one correction channel: measure, push
a correction, try again. When the correction channel is empty or wrong, the
loop spends its rejection budget on variations of the same failing approach.
The only diversity mechanism in the tree today is the heterogeneous proposal
ensemble of PSP-9 system 7, and its implementation is deliberately narrow:

* It fires **only at the Refine rung** of the recovery ladder
  (``crates/perspt-agent/src/runtime/ensemble.rs``), i.e. only after a node
  has already escalated once. The first, cheapest opportunity to try a
  different strategy — immediately after a ``RejectedNonDescending`` — draws
  no alternatives.
* Every arm replays the **same prompt** on a different route. Nothing varies
  the strategy, the presentation, or the plan; family diversity is the only
  degree of freedom.
* Each arm starts a fresh candidate from scratch and runs the full loop; there
  is no notion of a cheaper speculative probe, no shared no-good memory, and a
  failed arm's evidence evaporates.

What is missing is not a smarter gate but a **search plane in front of it**:
bounded speculative branches that may explore, temporarily regress, and fail,
with only measured winners submitted to the unchanged gate. The trilogy
explicitly permits this shape — Paper II's contract constrains *accepted*
transitions, not the proposer's internal iterations, and Paper III's kernel
constrains *effects*, wherever they originate. A branch that edits only its
isolated overlay under attenuated capabilities violates neither.

One Prompt for Every Provider
=============================

The production prompt surface of the entire agent is five inline string
literals:

       selected a different domain package.
   * - Adjudicator

     - Inline JSON-shape prose; the domain's ``adjudication_brief`` hook is
       never called.
   * - Architect

     - Hand-written JSON example of the ``update_graph`` payload that can

   * - Explorer

   * - Summarizer

No template engine exists in the prompt path, no provider conditioning exists
anywhere, and the correction channel discards most of what the domain
computes: ``push_correction`` sends only ``CorrectionDirection.instruction``
and drops ``target_paths``, ``target_symbols``, and ``rationale`` on the
floor. The richer per-language ``LanguageAdapter::correction_for``
implementations (seven residual classes for Rust) are shadowed by a four-arm
domain-level fallback and are reachable only from unit tests.

Meanwhile the reviewed Codex CLI and the reverse-engineered Claude Code
harnesses demonstrate — structurally, without reference to their prompt text —
that production harnesses condition instructions on provider and model
family, keep actor prompts narrow and stage-specific, version their prompts,
assemble them conditionally from typed state, and treat tool descriptions as
provider-facing surface distinct from tool authority. Perspt's governance
layer is stronger than either; its prompt layer does not exist. This PSP
supplies it under Perspt's rules: complete templates per provider route,
compiled and hashed, presenting typed state, with authority remaining
exclusively in Rust data.

What PSP-9 Left Unwired
=======================

The audit that precedes this PSP verified each of the following against the
tree rather than assuming it:

* **The finite-decision bound is not enforced.**
  ``AcceptedTrajectory::decision_bound`` and
  ``perspt_agent::toolloop::loop_decision_bound`` are called only from tests.
  The doc comment on the latter claims "exceeding it fails the run"; no
  production code path checks it. The loop is bounded today by ``max_turns``
  and the rejection budget only. A search plane that consumes gate decisions
  requires the bound to be a live predicate first.
* **``HardGatePolicy`` has zero runtime consumers.** Both domain packages
  declare ``required_stages``; the measurer ignores them and computes
  ``hard_pass`` from the plugin verifier profile
  (``crates/perspt-agent/src/candidate.rs``). A domain cannot currently make a
  declared stage load-bearing, and an undeclared optional check could silently
  become a hard predicate.
* **The architect bypasses the kernel.** The planning turn invokes the
  ``update_graph`` tool spec directly over the transport, outside the tool
  loop; the result is schema-validated but no capability is checked and no
  admissibility witness is produced. ``UpdateGraph`` is in
  ``WITHHELD_EFFECTS`` with no grant path, so the one effect Paper III calls
  privileged is exercised only ungoverned.
* **The accepted fold collides candidates.** ``replay_accepted_trajectory``
  (``crates/perspt-sdk/src/ledger.rs``) keys candidate energies by
  ``(node_id, generation)``; an ensemble round runs several candidates at the
  same key and their measurements overwrite one another, so replay can
  attribute the wrong energy to the accepted candidate. The ledgered gate
  event also omits ``observed_energy`` and ``best_accepted_before``.
* **Diagnostics are scraped, not parsed.** Rust diagnostics are recovered by
  ``strip_prefix("error[")`` over stdout lines; Python by lowercase substring
  match; every residual is emitted with ``score = 1.0`` and severity
  ``Error`` unconditionally; ``EvidencePayload::raw`` and ``::structured``
  are never populated. The only structured source in the tree (LSP
  ``publishDiagnostics``) does not feed energy.
* **Five duplicated actor loops.** Only the worker has failover, compaction,
  ledgered context deltas, and typed ``TurnObserved`` records; the explorer,
  architect, adjudicator, and summarizer each hand-roll their turn and record
  ad-hoc JSON blobs that replay cannot reconstruct.

Each item above is simultaneously a defect under PSP-9's own gates and a
prerequisite for this PSP's layers; the Reference Implementation therefore
lands them first, behavior-preserving, before any search or prompt code.

What the Papers Require
=======================

The trilogy constrains this design in four specific places:

* **Paper II Lemma 1 (finite acceptance).** The gate admits at most
  :math:`\lfloor V_0/\rho_{\text{gate}}\rfloor` strict descents and at most
  :math:`B` rejections. Search must *consume* this budget, never dilute it:
  one submitted branch candidate costs one gate decision, and no amount of
  branching may manufacture additional decisions. Lemma 1 below proves the
  bound is preserved and Gate X makes its violation falsifiable.
* **Paper III Definition 3.2 (admissibility kernel).** Branches act only
  through mediated effects on isolated overlays under attenuated capabilities
  with no promotion authority. Axiom 1 below inherits this wholesale; search
  adds no new effect path.
* **Paper III Theorem 7 (replay determinism).** Prompt programs and search
  state enter the ledger as digests and typed events; Theorem 2 below extends
  the deterministic fold to both. Resume fails closed when a compiled program
  cannot be reconstructed bit-exactly.
* **Paper III Lemma 5.1 / Corollary 5.2 (correlated validators).** Model
  family diversity across branches is a *search prior* — it may change which
  branch finds descent first. It is never an independence certificate, never
  a vote, and never enters selection. Selection is deterministic over
  measured, compiler-and-test quantities (Proposition 1).

============
Formal Model
============

This section fixes notation, states the axioms the runtime already enforces,
and proves the four properties the new layers must preserve. The discipline is
the trilogy's own: every claim names the predicate that would falsify it, and
the predicate runs (the Conformance Gates section maps each result to a gate).

Objects and Notation
====================

Let :math:`X` be the space of realized workspace states (content-addressed
snapshots over a canonical scope, per Paper I Definition 12.2). Fix a node
generation with baseline energy :math:`V_0`, gate margin
:math:`\rho_{\text{gate}} > 0`, and rejection budget :math:`B \in \mathbb{N}`.
Energy is the canonical quadratic
:math:`V(x) = \sum_e w_e \lVert r_e(x)\rVert^2` over the domain's residual
schema, evaluated only on realized states.

.. rubric:: Definition 1 (Accepted trajectory)

The accepted trajectory is the finite sequence
:math:`\mathcal{A} = (x_0, x_1, \dots, x_k)`, :math:`x_i \in X`, where each
transition is admitted by the Paper II gate

.. math::

   \operatorname{accept}(y) \;\Longleftrightarrow\;
   \operatorname{hard}(y) \;\lor\;
   V(y) \le V_{\text{best}} - \rho_{\text{gate}},

with :math:`V_{\text{best}} = \min_{i \le k} V(x_i)` the best accepted energy.
Every submission — accepted or rejected — appends exactly one decision to the
trajectory's decision sequence :math:`D = (d_1, d_2, \dots)`; rejections
additionally consume one unit of :math:`B`. This is implemented today by
``AcceptedTrajectory::submit_with_floor`` and is unchanged by this PSP.

.. rubric:: Definition 2 (Search forest)

For accepted state :math:`x_k`, a search forest is a finite set of branches

.. math::

   \mathcal{E}_k = \{\, b_1, \dots, b_n \,\},\qquad
   n \le n_{\max},

where each branch :math:`b` carries an internal state sequence

.. math::

   z_{b,0} = x_k,\quad z_{b,1},\ \dots,\ z_{b,T_b},

produced by mediated effects on an isolated overlay forked from the accepted
checkpoint of :math:`x_k`. **No descent condition applies to internal
states:** :math:`V(z_{b,t+1}) > V(z_{b,t})` is permitted for every internal
step. Internal states are not accepted states, are never promoted, and are
never written to the user workspace.

.. rubric:: Definition 3 (Branch candidate boundary and eligibility)

A branch may declare at most one *candidate boundary* per gate submission at
some internal state :math:`z_{b,t}`. The realized candidate
:math:`y = \operatorname{realize}(z_{b,t})` is *eligible* iff

.. math::

   E(y) \;=\;
   \underbrace{\Phi_{\text{barrier}}(y)}_{\text{operational barriers hold}}
   \;\land\;
   \underbrace{S_{\text{req}}(y)}_{\text{required hard-gate sensors ran}}
   \;\land\;
   \bigl(\operatorname{hard}(y) \lor V(y) \le V_{\text{best}} -
   \rho_{\text{gate}}\bigr)
   \;\land\;
   \underbrace{W(y, z_{b,0})}_{\text{witness descends from the branch root}}.

Only an eligible candidate is submitted; submission uses the ordinary gate of
Definition 1 with no modification. :math:`S_{\text{req}}` is evaluated
against ``HardGatePolicy::required_stages`` — the wiring this PSP adds — and
:math:`W` compares the candidate's ``CandidateStateWitness`` chain to the
recorded branch root checkpoint.

.. rubric:: Definition 4 (Prompt program and route resolution)

A prompt route is :math:`r = (a, f, m)` with transport adapter :math:`a`,
model family :math:`f`, and optional exact model :math:`m`. For stage set
:math:`S` (Section 23) and template universe :math:`\mathcal{T}`, resolution
is the function

.. math::

   R : (r, s) \;\longrightarrow\; \mathcal{T} \cup \{\bot\},\qquad
   R(r, s) = \begin{cases}
     t_{a,f,m,s} & \text{if an exact-model override exists,}\\
     t_{a,f,s}   & \text{else if a family template exists,}\\
     t_{\text{fb},s} & \text{else if } s \in S_{\text{domain}} \text{ and a
       declared fallback exists,}\\
     \bot        & \text{otherwise.}
   \end{cases}

:math:`R(r,s) = \bot` for a platform stage fails route activation
(fail-closed); for a domain stage it fails compilation unless the domain
manifest declares the fallback. A compiled program
:math:`\pi_{p,m,s} = \operatorname{compile}(R(r,s), v)` over variables
:math:`v` is deterministic: identical ``(template, version, v)`` yields
identical rendered bytes and identical digests.

.. rubric:: Definition 5 (Search budget)

A search budget is a vector
:math:`\beta \in \mathbb{N}^d` over the dimensions
(model turns, tool calls, mutations, verifier executions, tokens, elapsed
time, result bytes, gate decisions). Branch actions *claim* from
:math:`\beta` before executing; a claim is refunded only in its unspent part.
The budget is **non-replenishing**: the sequence of remaining budgets
:math:`\beta^{(0)} \ge \beta^{(1)} \ge \cdots` is monotone non-increasing in
every coordinate, and every branch action has a strictly positive minimum
claim :math:`c_{\min} > 0` in at least one coordinate.

.. rubric:: Axiom 1 (Effect mediation — Paper III Def. 3.2)

Every effect of every branch passes the five-clause admissibility kernel
under a capability attenuated from the session grant, with promotion
authority withheld. Search introduces no new effect path. (This is inherited,
not new: branches run the ordinary tool loop against overlay workspaces.)

.. rubric:: Axiom 2 (Sensor determinism)

A verifier stage identified by its sensor fingerprint (tool identity,
version, configuration hash) is a deterministic function of the realized
workspace state within a session. Residual normalization is defined per
immutable sensor profile. (Flaky sensors violate the axiom and must be
declared; an undeclared violation is detectable as a replay divergence.)

Results
=======

.. rubric:: Lemma 1 (Gate-decision conservation)

*A forest round that submits* :math:`m` *eligible branch candidates appends
exactly* :math:`m` *decisions to* :math:`D` *and consumes rejection budget
only for rejected submissions. Consequently Paper II Lemma 1's bound*

.. math::

   |D| \;\le\; N_{\text{gate}}
   \;=\; \left\lfloor \frac{V_0}{\rho_{\text{gate}}} \right\rfloor + B + 1

*is preserved under search.*

**Proof.** Internal branch steps produce measurements but call no gate API;
by construction (Definition 3) only candidate boundaries invoke
``submit_with_floor``, and each invocation appends exactly one
``GateDecisionRef``. For the bound: every accepted decision strictly lowers
:math:`V_{\text{best}}` by at least :math:`\rho_{\text{gate}}` (measured
descent) or is a hard pass; since :math:`V \ge 0` and hard passes terminate
the generation, at most
:math:`\lfloor V_0/\rho_{\text{gate}}\rfloor` descents occur. Rejections are
bounded by :math:`B` by the budget check, and one terminal decision (floor
stop, hard pass, or exhaustion certificate) closes the sequence. No search
event constructs a ``GateDecisionRef`` outside submission, so branching
cannot lengthen :math:`D`. ∎

The premise "no search event constructs a decision" is not an assumption but
a checked property: Gate X counts ``gate_decisions.len()`` deltas per
submitted candidate in the mechanism tests, and the loop refuses submission
:math:`N_{\text{gate}}+1` — the enforcement this PSP adds.

.. rubric:: Lemma 2 (Accepted-fold invariance)

*Let* :math:`L` *be a session ledger and*
:math:`\operatorname{foldAccepted}` *the accepted-trajectory projection*
(``replay_accepted_trajectory``) *after this PSP's re-keying. Let*
:math:`L_{\text{search}} \subset L` *be the events whose kinds belong to the
search alphabet* :math:`\Sigma_s` *=* ``{search_opened, branch_forked,
branch_strategy_selected, branch_observation, branch_candidate_measured,
branch_rejected, branch_abandoned, branch_selected, branch_merged,
no_good_recorded, search_closed}``. *Then*

.. math::

   \operatorname{foldAccepted}(L) \;=\;
   \operatorname{foldAccepted}(L \setminus L_{\text{search}}).

**Proof.** By case analysis over the fold's input alphabet. The re-keyed fold
transitions only on events of kind ``candidate_measured`` (updating
:math:`\text{latest}[(n, g, c)]` for node :math:`n`, generation :math:`g`,
candidate id :math:`c`) and ``gate_decision_recorded`` (emitting the entry
when accepted). Both kinds are disjoint from :math:`\Sigma_s`. A branch that
never submits produces only :math:`\Sigma_s` events, hence contributes
nothing to the fold. A branch that submits produces its
``candidate_measured`` and ``gate_decision_recorded`` events *as ordinary
trajectory events outside* :math:`\Sigma_s` — these are precisely the events
that must survive discarding, and they do. Removing
:math:`L_{\text{search}}` therefore removes no event the fold reads, and the
projections coincide. The re-keying by :math:`c` is what makes the fold
well-defined when several branch candidates share :math:`(n, g)`; without
it (the current tree) the lemma is false, which is the defect this PSP
fixes. ∎

.. rubric:: Theorem 1 (Bounded search termination)

*Every search forest closes after finitely many branch actions. Explicitly,
the number of branch actions is at most*

.. math::

   A_{\max} \;=\;
   \min\left(
     \frac{\lVert \beta \rVert_1}{c_{\min}},\;
     n_{\max}\, T_{\max}
   \right),

*and the number of gate submissions from the forest is at most*
:math:`\min(\beta_{\text{gate}},\; N_{\text{gate}} - |D_{\text{prior}}|)`.

**Proof.** Each branch action claims at least :math:`c_{\min}` in some
budget coordinate (Definition 5) and refunds at most its unspent part, so the
total claimed over the forest's lifetime is monotone increasing and bounded
by :math:`\lVert \beta \rVert_1`; hence at most
:math:`\lVert\beta\rVert_1 / c_{\min}` actions occur. Independently, the
forest opens at most :math:`n_{\max}` branches (expansion policy) each with a
per-branch action bound :math:`T_{\max}` from its turn budget. Gate
submissions claim the gate-decision coordinate
:math:`\beta_{\text{gate}}` *and* append to :math:`D`, so they are bounded by
both the budget and Lemma 1's remaining bound. When any bound reaches zero
the forest transitions to ``SearchClosed``; no replenishment exists by
Definition 5, so closure is reached in finite time. ∎

.. rubric:: Theorem 2 (Replay determinism over programs and search)

*Under Axiom 2 and the provenance rules of this PSP (compiled-program digests
in every model-call event, prompt manifest digest and program digest in the*
``ControlFrame``, *bundles pinned by content address for the session), the
deterministic fold of Paper III Theorem 7 extends to search and prompt
state: two replays of the same ledger prefix reconstruct identical accepted
projections, identical branch states, identical remaining budgets, and
identical compiled prompt bytes, performing no provider calls.*

**Proof sketch.** By structural induction on the ledger prefix. The fold
state is (accepted projection, forest state, budget vector, conversation
projections, program registry). Base: the seed events fix the initial state
and the pinned bundle set; built-in templates are compiled from
``include_str!`` sources whose hashes are recorded in the manifest digest.
Step: each event kind has a single-valued transition — search events update
forest/budget state by pure arithmetic; ``conversation`` deltas are already
digest-chained (PSP-9 system 14); a model-call event names
``(template_id, version, source_hash, rendered_hash, program_digest)``, and
by Definition 4 compilation is deterministic, so the replayer either
reproduces the identical bytes or detects a digest mismatch and fails
closed — it never silently diverges. Raw model outputs are read from the
ledger (recorded before parsing), never re-sampled, so no provider call
occurs. Hence the fold is a deterministic function of the prefix. ∎

.. rubric:: Proposition 1 (Selection is a deterministic total order)

*The branch selection rule — (1) hard pass before measured descent, (2)
lowest normalized energy, (3) greatest reduction of the targeted residual
cluster, (4) lowest verifier/model/effect cost, (5) lexicographically least*
``branch_id`` *— is a total order on any set of measured candidates with
distinct branch ids, and selection (its minimum) is deterministic.*

**Proof.** Keys (1)–(4) are numeric comparisons on realized measurements,
each a total preorder; their lexicographic composition is a total preorder.
Key (5) is a total *order* on distinct branch ids and refines any remaining
tie, so the composition is antisymmetric: two candidates comparing equal
must share a branch id, contradiction. A finite nonempty set under a total
order has a unique minimum; measurements are ledgered realized quantities
(Axiom 2), so re-evaluation yields the same minimum. No model confidence,
vote, or sampled quantity participates. ∎

Non-Claims
==========

Stated in the house discipline — what this PSP deliberately does **not**
claim, so that no reader or implementer strengthens it by accident:

* **Search improves reachability only.** A forest makes it more likely that
  *some* eligible candidate is found within budget. It creates no stability,
  correctness, or independence claim; every guarantee still enters through
  the unchanged gate on the realized winner.
* **Family diversity is a prior, not a certificate.** Branch routes from
  different model families may fail differently; Paper III Corollary 5.2
  forbids converting that into a risk bound without matched labeled joint
  verdicts. Nothing in the search plane reports one.
* **Internal branch states carry no claims at all.** They may regress, break
  the build, or contradict each other; none of it is observable outside the
  branch except through the bounded evidence digest and no-goods.
* **No coding** :math:`\delta_r` **claim.** Realizability remains
  ``not_claimed`` for the coding domain exactly as resolved in PSP-9;
  branches change nothing about proxy geometry.
* **Prompt programs change presentation, never authority.** A template
  cannot grant, widen, or describe-into-existence a capability; schemas,
  effects, risks, and footprints remain authoritative Rust data (Gate L is
  unchanged).

======================================

*Owner:* ``perspt-sdk::search`` *(types, selection);*

       pub usage: SearchUsage,
   }

   pub enum SearchBranchState {
       Ready,
       Running,

The accepted trajectory remains owned by ``AcceptedTrajectory``;
``SearchForest`` holds no reference to it and cannot mutate it. The only
channel from forest to trajectory is an eligible candidate submitted through
the ordinary gate.

.. graphviz::

       rankdir=LR;

       Running -> Running [label="mediated edits,\nincremental probes\n(uphill allowed)"];

Each branch:

* receives an isolated candidate workspace **seeded from the accepted
  checkpoint** — the existing ``export_accepted()`` /
  ``restore_exported()`` seed mechanism, not a fork of the live user
  workspace, so :math:`z_{b,0} = x_k` is a recorded, witnessed fact
  (``root_checkpoint``);
* receives a capability attenuated from the session grant with promotion and
  ``UpdateGraph`` withheld (the existing ``WITHHELD_EFFECTS`` +
  ``GrantPolicy::mint`` path — no new authority machinery);
* holds an independent provider-neutral conversation projection
  (``LoopContext``), digest-chained into the ledger like any worker context;
* may perform bounded edits and incremental verifier probes that create **no
  gate decisions** and observe the ordinary effect-boundary safety barriers
  and bounded verification cadence;
* produces a realized ``BranchMeasurement`` only at a declared candidate
  boundary, where *all* ``HardGatePolicy::required_stages`` must have run
  (Definition 3); and
* is discarded completely on rejection or abandonment — the overlay is
  destroyed, its conversation is never replayed into another branch, and
  only its no-goods and bounded evidence digest survive.

**Selection is deterministic** (Proposition 1): hard pass first, then lowest
normalized energy, then greatest reduction of the branch's targeted residual
cluster, then lowest verifier/model/effect cost, then lexical ``branch_id``.
No voting; no model confidence; no sampled quantity.

20. Adaptive Expansion and the Search Budget
============================================

*Owner:* ``perspt-sdk::search`` *(policy types);*
``perspt-agent::runtime::search`` *(triggers).* *Replaces the Refine-rung
ensemble draw of PSP-9 system 7; the recovery ladder itself (Retry /
Fallback / Refine / Escalate, the shared recovery pool, and containment) is
unchanged — the Refine rung now opens a forest instead of drawing an
ensemble round.*

The first branch uses the primary actuator route with the domain's default
strategy. Additional, deliberately diverse branches are opened only on a
measured trigger:

* a ``RejectedNonDescending`` gate decision;
* the same dominant residual cluster recurring without a changed correction
  route;
* an empty ``CorrectionPacket`` (no honest correction channel — Section 26);
* a measured energy plateau across the branch's probes;
* a failed strategy-specific assumption (declared by the strategy, checked
  deterministically); or
* the branch exhausting its local retry allocation while the shared search
  budget remains.

Expansion is bounded: **one initial branch, at most three branches, one
running at a time** (release defaults; ``[exploration]`` configuration).
Diversity preference on expansion: a different strategy first, a different
model family second (``require_distinct_family`` semantics carry over from
the removed ensemble policy as a search prior).

.. code-block:: rust

   pub struct SearchBudget {
       pub model_turns: u32,
       pub tool_calls: u32,
       pub mutations: u32,
       pub verifier_runs: u32,
       pub tokens: u64,
       pub wall_clock_secs: u64,
       pub result_bytes: u64,
       pub gate_decisions: u32,   // claims against Lemma 1's remainder
   }

The budget is a single non-replenishing pool per forest (Definition 5),
claim/refund in the style of the existing ``SharedRecoveryPool``: branches
claim before acting and refund only unspent claims. Three of its dimensions —
tokens, wall-clock, verifier executions — do not exist as budgets anywhere in
the tree today and are introduced here.

**Gate consumption is counted from the trajectory itself**:
``trajectory.gate_decisions.len()`` deltas, never rejection or recovery
counters. A branch selected for submission consumes exactly one
candidate-boundary gate decision (Lemma 1; Gate X). The loop refuses the
:math:`N_{\text{gate}}+1`-th submission — the enforcement debt paid in
Reference Implementation Phase 1.

**Duplicate suppression.** A strategy whose declared assumptions match a
recorded no-good, or a candidate whose realized state root equals an already
measured root, is not re-executed; the forest records the refusal and moves
to the next trigger or closes.

21. Search Evidence, No-Goods, and the Re-Keyed Accepted Fold
=============================================================

*Owner:* ``perspt-agent::toolloop`` *(events);* ``perspt-sdk::ledger``
*(fold).*

Failed paths must remain useful without entering task state. Eleven event
kinds join the production event stream (as typed ``LoopEvent`` variants with
the established ``Custom { kind: "tool_loop" }`` ledger encoding — **not** as
new variants of the dormant typed ``LedgerEvent`` surface):

.. code-block:: text

   search_opened            branch_forked          branch_strategy_selected
   branch_observation       branch_candidate_measured
   branch_rejected          branch_abandoned       branch_selected
   branch_merged            no_good_recorded       search_closed

Every search event carries ``forest_id``, ``branch_id``, and — where a
measurement exists — ``candidate_id``.

**No-goods are deterministic or they are not no-goods.** ``no_good_recorded``
may contain only constraints a deterministic sensor supports: a compiler
error code, a failed test identity, an incompatible API contract witnessed by
a diagnostic, an unchanged realized state hash, a denied capability. Model
interpretations remain advisory observations and cannot enter the no-good
store (Gate AB).

**Cross-branch context is bounded.** Another branch receives a
``SearchEvidenceDigest`` — dominant residual cluster, no-good references,
tried strategy identities, byte-bounded — never another branch's raw
conversation. This prevents a failed path's context from polluting every
route, and keeps each branch's conversation projection independently
foldable.

**The re-keyed fold.** ``replay_accepted_trajectory`` currently keys
candidate energies by ``(node_id, generation)``; several candidates at one
key overwrite one another, so the accepted projection of an ensemble ledger
is already wrong today and a forest would make it worse. This PSP:

* adds ``candidate_id`` to ``candidate_measured``,
  ``gate_decision_recorded``, and ``durable_candidate_checkpoint`` payloads
  (serde-defaulted so pre-PSP-10 ledgers still fold);
* ledgers the full ``GateDecisionRef`` — ``observed_energy`` and
  ``best_accepted_before`` are recorded, not recovered by correlation; and
* re-keys the fold by ``(node_id, generation, candidate_id)``.

With the re-keying, Lemma 2's invariance

.. math::

   \operatorname{foldAccepted}(L) =
   \operatorname{foldAccepted}(L \setminus L_{\text{search}})

holds and is enforced as a property test over every search mechanism-check
ledger (Gate W).

22. Graph Staging and the Global Integration Gate
=================================================

*Owner:* ``perspt-agent::runtime::integrate`` *(new);*
``perspt-agent::runtime::dispatch`` *(changed).*

Two nodes can each pass their own verifier suite and still fail together —
an interface drifts, a dependency conflicts, a test only breaks under the
combined state. Today ``fold_completion`` promotes each node winner to the
user workspace as it settles; composition failures escape to the user. This
PSP interposes a staging layer:

.. graphviz::

   digraph staging {
       rankdir=LR;
       node [shape=box, style=rounded, fontsize=10];
       w1 [label="node winner A\n(realized seeds)"];
       w2 [label="node winner B\n(realized seeds)"];
       sr [label="graph staging root\n(content-addressed\nseed set)"];
       io [label="integration overlay\n(CandidateWorkspace)"];
       gg [label="global gate:\nfull suite +\nimmutable oracle\non combined state"];
       up [label="atomic promotion\n(certify + commit,\nGraphWrite lease)"];
       fail [label="restore prior staging\nroot; record conflicting\nnode evidence",
             style="rounded,dashed"];
       w1 -> sr; w2 -> sr;
       sr -> io [label="typed interface /\nrestriction checks\nacross graph edges"];
       io -> gg; gg -> up [label="pass"];
       gg -> fail [label="fail"];
   }

* Node winners are accepted into a **graph staging root** — an accumulated,
  content-hash-keyed seed-file set — not promoted to the user workspace.
* Dependent nodes fork their branch roots from the latest staging root, so
  downstream work builds on upstream winners without touching the user tree.
* Disjoint concurrent winners merge deterministically into an integration
  overlay; typed interface/restriction checks run across graph edges.
* **One global verifier gate** runs on the combined state — the full domain
  suite plus the existing ``immutable_test_oracle`` (candidate code against
  pre-image tests), so a winner cannot certify the integration by weakening
  an oracle.
* Only the globally verified integration root is promoted, atomically,
  through the **unchanged** hardened path (``certify_promotion`` →
  ``commit_promotion`` with R5 write-ahead bracketing, under the single
  ``GraphWrite`` lease). Integration failure restores the prior staging root
  and records the conflicting node evidence; partial promotion is impossible
  (Gate AA).

This makes the work graph the task trajectory and the search forest its
speculative proposal mechanism — per node, branches propose; per graph, the
staging root accumulates; per session, one atomic promotion commits.

Digests follow the ``GrantPolicy::canonical_bytes`` discipline — a

**Rendering engine.** ``minijinja`` 2.x, pinned, ``default-features =
false``, and encapsulated: no minijinja type appears in any public SDK
signature, and domain consumers never touch the engine. The restriction set
is exactly what the crate's feature flags and APIs can enforce, stated
honestly:

* strict undefined variables (``UndefinedBehavior::Strict``) — an unknown or
  missing variable fails compilation;
* no filesystem loader — templates come only from ``include_str!`` or pinned
  bundle artifacts;
* no ``include`` / ``extends`` / ``import`` — the ``multi_template`` feature
  is off, so the syntax is a template error;
* no macros (feature off), no arbitrary functions, no runtime code;
* only field access, conditionals, bounded loops, and an explicit allowlist
  of SDK-registered deterministic formatting filters;
* "bounded" is enforced operationally: an engine fuel limit
  (``set_fuel``) plus a hard cap on rendered size checked after rendering —
  not static loop analysis, which the engine does not offer;
* no auto-escaping (output is model-facing text, not HTML); and
* variables are supplied as deterministically ordered maps (``BTreeMap``),
  so identical inputs render identical bytes (Definition 4).

Built-in templates are parsed and validated once at first use behind
compiled registries; a template that fails validation fails the build of its
owning crate's tests, not a session at 2 a.m.

25. Template Ownership, Manifests, and External Bundles
=======================================================

*Owner:* each template-owning crate; validation in ``perspt-sdk::prompt``.

No global fragment directory, no cross-provider prose composition: **every
provider-stage prompt is a complete template.** Two providers' templates for
one stage may say similar things; they are still separate files with
separate hashes, because splicing shared fragments is how one provider's
phrasing quietly leaks into another's and how diffs stop meaning anything.

.. code-block:: text

   crates/perspt-agent/prompts/            # PLATFORM (D1)
     manifest.toml
     fallback/
     openai__open_ai_gpt/
     anthropic__anthropic_claude/
     gemini__google_gemini/
     overrides/

   crates/perspt-coding/prompts/           # coding domain
     manifest.toml
     fallback/
     openai__open_ai_gpt/
     anthropic__anthropic_claude/
     gemini__google_gemini/
     overrides/

The platform library owns: session bootstrap and platform behavior;
capability and permission explanation; the governed graph-update protocol;
tool discovery; external-effect reconciliation; the conversation-compaction
narrative; universal actor lifecycle and write-ahead behavior. The coding
library owns: repository exploration; search-strategy generation; branch
proposal; compiler/test-directed correction; candidate review; coding
adjudication; failed-path evidence summarization. Other domains follow the
same contract; ``perspt-research`` ships ``fallback/`` only until content
work justifies family variants.

Each ``manifest.toml`` records, per template: id, version, stage, route,
role, variable schema, maximum rendered size, owner, rationale, review date,
and source hash. The manifest digest is part of the session's provenance
(Theorem 2).

**Tool descriptions.** ``ToolEntry`` separates authority from presentation
while preserving every existing authority field
(``effect``, ``risk``, ``schema``, ``footprint``, ``proposal_bindings``,
``durable``, ``origin`` — all unchanged):

.. code-block:: rust

   pub struct ToolEntry {
       pub name: String,
       pub discovery_summary: String,          // provider-neutral, trusted;
                                               // the ONLY text tool_search
                                               // scores (determinism)
       pub description_templates: Option<ToolDescriptionLibrary>,
       // ... every existing field unchanged ...
   }

The final ``ToolSpec.description`` is compiled for the selected provider
route (``to_spec_for_route``); a missing description library means the
existing provider-neutral description, so the change is additive. MCP
descriptions remain untrusted variables wrapped by a compiled local
provider-specific description template — the current
``[untrusted MCP description]`` prefix becomes a template obligation instead
of a ``format!`` convention. Prompt templates cannot mint or widen
authority; nothing model-facing feeds back into the catalog's effect, risk,
or footprint data.

**External prompt bundles.** Built-in templates are compiled into their
owning crate. Explicit external bundles use the same manifest and directory
contract:

.. code-block:: toml

   [prompts]
   bundles = ["/path/to/domain-prompts"]

Bundles are compiled and validated at session startup, copied into the
content-addressed artifact store, and pinned for the complete session;
changes on disk cannot alter a running or resumed session. Domain templates
may be replaced by a compatible bundle. Replacing **platform** templates
additionally requires ``--allow-core-prompt-override``, and its use is
ledgered as a governance degradation. ``ControlFrame`` gains
``prompt_program_digest`` and ``prompt_manifest_digest``
(serde-defaulted; empty means a pre-PSP-10 checkpoint and resume proceeds
legacy-permissive; non-empty means resume fails unless the exact compiled
program is reconstructed from built-ins or stored bundle artifacts —
Gate Z).

26. Structured Verifier Plane and Correction Packets
====================================================

*Owner:* ``perspt-coding::diag`` *(new);* ``perspt-sdk::residual``
*(packet type);* ``perspt-agent::candidate`` *(wiring).*

Text-line scraping is replaced by structured adapters, one per language,
behind the existing ``LanguageAdapter`` trait:

* **Rust** — ``cargo``/``rustc`` JSON messages
  (``--message-format=json``): codes, spans, children, applicable
  suggestions.
* **Python** — pyright JSON output and pytest machine-readable reports with
  test identity and trace attribution.
* **TypeScript** — structured ``tsc`` machine output
  (``--pretty false`` parse).

Sensor version and configuration fingerprints are preserved in
``SensorRef`` (Axiom 2). ``EvidencePayload::raw`` and ``::structured`` —
present in the type since PSP-8, populated by nothing — carry the actual
diagnostic evidence. Cascaded errors are clustered by root cause before
scoring, and magnitude is normalized per immutable sensor profile instead of
the current unconditional ``score = 1.0``: two hundred cascade errors from
one missing import are one cluster, not two hundred units of energy.

**The two correction systems become one.** The domain-level four-arm
``correction_for`` delegates to the per-language
``LanguageAdapter::correction_for`` (currently dead code), and all resulting
directions fold into a single coherent packet:

.. code-block:: rust

   pub struct CorrectionPacket {
       pub dominant_cluster: ResidualClusterRef,
       pub diagnostics: Vec<StructuredDiagnosticRef>,
       pub affected: AffectedSet,        // paths, symbols, spans,
                                         // tests, graph edges
       pub operators: Vec<CorrectionOperator>,
       pub expected_footprint: FootprintSpec,
       pub follow_up_stages: Vec<String>,
       pub no_goods: Vec<NoGoodRef>,
       pub uncertainty: Vec<MissingSensorDecl>,
   }

``AgentDomainPackage`` gains defaulted, object-safe methods so both existing
domains compile unchanged until they opt in:

.. code-block:: rust

   fn prompt_library(&self) -> &dyn DomainPromptLibrary;
   fn search_strategies(&self, context: &SearchContext) -> Vec<SearchStrategy>;
   fn correction_packet(&self, residuals: &[ResidualEvent])
       -> Option<CorrectionPacket>;
   fn compare_branch_measurements(&self, root: &DomainMeasurement,
       candidates: &[BranchMeasurement]) -> BranchSelection;

``push_correction`` renders the packet through the ``BranchCorrect``
template — ``target_paths``, ``target_symbols``, and ``rationale`` stop
being dropped. **An empty packet transitions to search expansion or
escalation; it never produces a generic blind retry string.** The two
inline "did not descend…" fallback strings are deleted with it.

**Gate semantics become lexicographic and declared.** The gate profile is:
(1) operational and immutable-oracle hard constraints; (2) required verifier
stages; (3) targeted residual improvement; (4) normalized soft energy.
``HardGatePolicy`` becomes the actual source of required stages: a declared
stage that did not run fails measurement with a blocking
``SensorUnavailable`` residual and ``hard_pass = false``; an undeclared
optional check may add residuals but can never silently become a hard
predicate. Internal branch edits may move uphill; only candidate boundaries
submit to ``AcceptedTrajectory``.

**Model-conditioned strategy statistics.** Provider-specific templates
encode different presentations of the same typed state, never different
authority or acceptance rules. The store tracks

.. math::

   \hat{p}\bigl(\text{eligible descent} \mid
   \text{adapter}, \text{family}, \text{stage},
   \text{strategy}, \text{residual stratum}\bigr)

for route ordering, activated only past a minimum sample floor (the PSP-9
cold-start discipline: no prior masquerades as evidence). Route ordering is
frozen within a branch. Model-family diversity remains a search prior, never
an independence certificate.

27. Universal Actor Turns and Kernel-Mediated Graph Update
==========================================================

*Owner:* ``perspt-agent::turn`` *(new).*

One ``ActorTurnRunner`` executes every stochastic actor — worker, explorer,
architect, adjudicator, evidence summarizer, capability probe, and any
external-tool-enabled actor:

1. resolve the provider prompt route (system 24);
2. compile and ledger the platform and domain prompt programs;
3. call the transport, with the failover chain every actor now shares
   (today only the worker has one);
4. **record the raw observation before any inspection** — a typed
   ``turn_observed`` event with an actor tag, replacing the four ad-hoc
   ``record_custom`` JSON blobs that replay cannot reconstruct;
5. parse deterministic output (fail-closed on schema mismatch);
6. convert tool calls or graph changes into governed proposals; and
7. record the result and the updated conversation projection.

**Architect graph changes pass through the kernel.** The runtime holds a
runtime-minted ``UpdateGraph`` capability — never granted to workers,
``WITHHELD_EFFECTS`` unchanged — and the architect's ``update_graph``
proposal runs ``check_full_admissibility`` like every other effect. A
kernel-refused revision falls back to the deterministic initial graph and is
ledgered. The inline hand-written JSON example in the architect prompt is
replaced by a variable rendered from the actual ``ToolSpec``, so the schema
shown to the model cannot drift from the schema enforced on it.

.. rubric:: Conformance Gates

Lettering continues :psp:`000009` (J–V); this PSP adds W–AC. Each gate names
its falsifying predicate; the predicate runs in the mechanism checks.

.. list-table::
   :header-rows: 1
   :widths: 6 40 54

   * - Gate
     - Requirement
     - Falsifying predicate
   * - W
     - **Branch isolation.** Rejected and abandoned branches leave the
       accepted workspace, the accepted fold, and the user workspace
       unchanged.
     - A ledger where removing all search-alphabet events changes
       ``replay_accepted_trajectory`` output, or a rejected branch whose
       overlay teardown left any user-workspace path changed.
   * - X
     - **Gate-decision conservation.** Exactly one gate decision per
       submitted branch candidate; the enforced bound
       :math:`N_{\text{gate}}` refuses further submissions; search cannot
       continue past the remaining bound.
     - ``gate_decisions.len()`` delta ≠ number of submitted candidates in
       any forest round, or a submission accepted after the bound is
       reached.
   * - Y
     - **Prompt-route determinism.** Resolution follows exact-model →
       family → declared-fallback; platform stages fail closed; identical
       inputs yield identical rendered bytes and digests.
     - Two compilations of one ``(template, version, variables)`` differing
       in ``rendered_hash``, or a platform stage activating with a missing
       route, or a domain fallback used without a manifest declaration.
   * - Z
     - **Program provenance.** Every model call ledgers its compiled
       programs (ids, versions, source and rendered hashes, program
       digest); resume fails unless the exact program reconstructs from
       built-ins or pinned bundle artifacts; platform override without
       ``--allow-core-prompt-override`` is rejected and with it is
       ledgered as degradation.
     - A model-call event with no program digest, a resume that proceeds
       past an unreconstructable digest, or an unledgered platform
       override.
   * - AA
     - **Integration atomicity.** Only the globally verified integration
       root is promoted, atomically; integration failure restores the
       prior staging root; partial promotion is impossible.
     - Any user-workspace state containing one node winner but not the
       rest of its verified integration root.
   * - AB
     - **No-good soundness.** ``no_good_recorded`` contains only
       deterministically supported constraints; model text cannot enter
       the no-good store.
     - A no-good whose supporting evidence is not a compiler code, test
       identity, contract diagnostic, state hash, or capability denial.
   * - AC
     - **Search-budget monotonicity.** One non-replenishing pool per
       forest; claims precede actions; refunds never exceed claims; a
       closed forest cannot reopen.
     - A remaining-budget coordinate that increases beyond a recorded
       refund, an action with no preceding claim, or events after
       ``search_closed``.

.. rubric:: Practical Decisions

Decisions taken here with their prices, in the house format:

* **Sequential branches only (max three).** Price: no wall-clock win from
  parallel speculation. Bought: no second DuckDB writer, no lease
  contention, no overlay/witness races; the eager-copy workspace cost stays
  linear and measured.
* **minijinja behind the SDK abstraction** rather than a hand-rolled
  substitution engine. Price: one new dependency in the SDK's tree. Bought:
  real conditionals and loops without inventing a dialect; the restriction
  set above is enforceable with features off and fuel on; no minijinja type
  escapes, so replacing the engine later is an implementation detail.
* **Byte-identical template migration first.** The five inline prompts move
  into ``fallback/`` templates verbatim and family directories start as
  copies; provider divergence is later content-only work. Price: no
  immediate quality win. Bought: a snapshot matrix that proves the
  migration changed nothing, so every later prompt change is a reviewed
  diff against a known baseline.
* **Search events ride the production ``Custom { kind }`` encoding** rather
  than reviving the dormant typed ``LedgerEvent`` variants. Price: the
  typed surface stays dormant. Bought: one live event path, one fold, no
  dual-recording ambiguity; re-unification is left to a future PSP.
* **The ensemble and exploration APIs are removed, not deprecated.** Price:
  a breaking config change (``[ensemble]`` produces a pointed migration
  error). Bought: one search plane instead of three overlapping
  mechanisms; PSP-9 set the precedent and the consumers are few.

=========
Rationale
=========

**Why a search forest instead of a wider ensemble.** The ensemble of PSP-9
system 7 varies exactly one thing — the model family — at exactly one
moment — the Refine rung — and pays full loop cost per arm. Real failed
attempts differ earlier and cheaper: a wrong strategy, a wrong plan, a wrong
presentation. The forest varies strategy, route, and prompt program; opens
on measured triggers rather than after escalation; lets branches probe
incrementally instead of running the full loop; and preserves the ensemble's
two disciplines (energy selection, one decision per candidate) as proved
properties rather than code comments. The ensemble's product hypothesis —
heterogeneous routes fail differently — survives as an expansion prior and
remains subject to ablation.

**Why complete templates per provider, not composed fragments.** Fragment
composition optimizes writing prompts; complete templates optimize *reading*
them. A reviewer of ``anthropic__anthropic_claude/branch_correct.j2`` sees
exactly what that model receives at that stage; a diff between two routes is
a real diff; a bad edit to one provider cannot leak into another through a
shared fragment. The cost — duplicated prose across families — is paid
deliberately, and the manifest's per-template hash keeps each copy
accountable.

**Why prompt identity is (adapter, family), never provider id.** Provider
ids name credentials and endpoints; families name instruction-following
behavior. The same Qwen behaves the same behind two gateways, and a
GPT-specific template sent to a Llama on an OpenAI-compatible endpoint is a
category error the resolution rule makes unrepresentable.

**Why selection admits no model confidence.** Confidence is a sampled,
uncalibrated, provider-shaped quantity; energy and hard passes are
compiler-and-test quantities. Paper III's rule — stochastic components
propose, deterministic admissibility commits — is the entire reason the
gate's guarantees survive search (Proposition 1 depends on it).

**Why the structural lessons of Codex and Claude Code enter without their
text.** What those harnesses demonstrate is architecture: provider- and
model-conditioned instructions, narrow stage prompts, detailed tool
contracts, conditional assembly, versioning. Their prompt prose is
harness-specific, unversionable here, and legally and technically
unportable. This PSP adopts the structure under Perspt's governance and
writes its own text, snapshot-tested from day one.

**Why enforcement debts land first.** A search plane on top of an
unenforced decision bound would *weaken* the platform — more candidates,
same unchecked ceiling. Paying the debts first (bound enforcement, hard-gate
wiring, kernel-mediated graph update, fold re-keying) is what makes the
forest's lemmas true statements about the shipped system rather than about
an idealized one.

.. rubric:: Test and Acceptance Plan

*Search invariants* (Phase 8): a branch increases energy internally and
later produces an accepted descent; rejected/abandoned branches leave the
accepted workspace and fold unchanged; every branch starts from the
recorded accepted root; one non-replenishing budget terminates search;
exactly one gate decision per submitted candidate; no continuation past
the remaining decision bound; duplicate realized roots and known no-goods
are not re-executed; an empty correction packet expands or escalates,
never retries generically; crash/resume reconstructs branch state, prompt
programs, budgets, and accepted root exactly.

*Prompt matrix* (Phases 5–6): the three families resolve distinct complete
templates per stage once family content diverges (identical-by-copy until
then, by design); exact-model overrides beat family templates; missing
domain routes use the declared fallback; missing platform routes fail
closed; unknown/missing variables fail compilation; rendered output and
hashes are deterministic; prompt-visible tool names match the effective
governed catalog; bundles are pinned and replayable; platform override
without the flag is rejected, with the flag is ledgered; no production
``Conversation::with_system`` literal remains outside the prompt
libraries, tests, probes, and examples.

*Verifier and graph behavior* (Phases 6, 10): structured diagnostics
preserve codes, spans, suggestions, test identities, and root-cause
grouping; declared stages control hard pass; two node candidates passing
independently but failing composed are rejected by the integration gate;
disjoint winners merge deterministically; integration failure restores the
prior staging root.

*Evaluation* (Phase 11): matched Rust and Python suites under identical
model, context, tool, token, and elapsed budgets across six arms — native
harness; Perspt single-branch with prompt programs; plus structured
corrections; plus adaptive search; plus multi-family adaptive search; plus
graph integration. Primary metrics: hidden-test hard-pass rate, escaped
regressions, time to accepted result, token/tool/verifier cost, branch
duplication, correction effectiveness, recovery success, replay validity.
Energy remains diagnostic until sensor normalization passes its own
calibration gate. Adaptive expansion becomes the release default only when
it improves or preserves hidden-test success versus single-branch,
materially reduces repeated identical failures, preserves zero escaped
hard-gate regressions in the acceptance fixtures, and passes live runs on
at least two model families (the third family remains credential-blocked;
scripted transports cover the three-family invariance, per the PSP-9
precedent).

=========================
Resolved Design Decisions
=========================

1. **Platform templates live in ``perspt-agent``** (D1). ``perspt-core``
   cannot own SDK-typed compiled registries without breaking the PSP-9
   layering rule, and a dedicated crate would add a workspace member
   without adding a seam. The term is "platform templates" throughout
   (D2).
2. **Branch concurrency is one** (D4). Sequential execution, at most three
   branches, is the normative release shape; parallel overlays are future
   work gated on a copy-on-write workspace and a second-writer store
   story.
3. **Search events use the production event path** — typed ``LoopEvent``
   variants with the ``Custom { kind }`` ledger encoding. The dormant
   typed ``LedgerEvent`` surface is not extended by this PSP.
4. **The finite-decision bound is enforced, not documented.** Its
   enforcement is Phase 1 and precedes all search code.
5. **Prompt identity is (adapter kind, model family, optional exact
   model).** The configured provider id never selects a template.
6. **Byte-identical migration before divergence.** Family template
   directories start as copies of ``fallback/``; every later divergence
   is a reviewed content diff against snapshots.
7. **Statistics activate at a sample floor.** Route-ordering statistics
   (system 26) ship dark and activate per stratum only past the declared
   floor, mirroring the PSP-9 calibration cold-start rule.

=====================
Remaining Open Issues
=====================

* **Copy-on-write branch overlays.** The eager-copy workspace bounds
  branch count in practice; an overlayfs/reflink-based fork would change
  the economics and unlock measured parallel speculation. Requires the
  witness chain to survive the new fork mechanism.
* **Where prompt divergence pays.** Family-specific template content is
  authorized by this PSP but not written; each divergence should enter
  with a benchmark delta attached, not on taste.
* **No-good generalization.** A no-good is currently exact (code, test,
  hash). Whether safe generalizations (e.g. "any strategy touching path
  P with operator O") can stay deterministic is open; until then only
  exact no-goods are recorded.
* **Unifying the dormant typed ledger surface.** The ``Custom { kind }``
  encoding is now load-bearing for search; folding the 23 dormant typed
  variants into one story is deferred to a future PSP.
